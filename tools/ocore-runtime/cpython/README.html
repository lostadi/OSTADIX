Full CPython source capture

full.recipe.json retains the exact CPython source pin from the original recipe and uses the frozen capture worker. Its build-inventory helper is additionally bound to exact SHA-256 bytes in each manifest command. The earlier flat recipe and its recorded captures remain unchanged.

This is a hosted Linux source-build profile. SQLite, Tcl/Tk, readline, DBM/GDBM, and the other applicable standard-library extensions must configure as enabled. Missing or disabled modules fail before the native build. The Darwin-only _scproxy module is explicitly inapplicable in this profile; arbitrary n/a reclassification is rejected.

Provide the complete hosted development headers/library interfaces through CPPFLAGS, LDFLAGS, and the upstream dependency flag variables, including LIBSQLITE3_CFLAGS/LIBSQLITE3_LIBS, TCLTK_CFLAGS/TCLTK_LIBS, GDBM_CFLAGS/GDBM_LIBS, and LIBREADLINE_CFLAGS/LIBREADLINE_LIBS where needed. Record exact package/source receipts. Extracting hosted libraries does not lower their implementations through O-core.

Run the generic source-capture command with empty build/capture directories and matching LLVM 22.1.6 drivers:

python3 scripts/ocore_runtime_capture.py capture \
  tools/ocore-runtime/cpython/full.recipe.json \
  --source SOURCE --build BUILD --output CAPTURE --jobs 2 \
  --unit-inventory BUILD/full-unit-inventory.json \
  --cc CLANG --cxx CLANGXX --llvm-nm LLVM_NM

The helper records the original upstream make --dry-run all commands, checks the actual native source invocations against the entire configured graph, and includes archive and extension outputs in membership evidence. Implementation helpers remain selected for lowering. Configure probes retain explicit stage, log, and membership evidence. Assembly sources remain required and fail closed until their import path exists.

This inventory establishes source-build accounting only. Complete imported functions/globals, dependency implementations, native OSTADIX platform services, linking, resources, compiler witnesses, and all-three-ISA execution remain separate required gates. A successful hosted build is not a completed native runtime or compiler.
