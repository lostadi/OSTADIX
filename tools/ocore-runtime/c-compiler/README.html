Capture the original compiler

Use a clean checkout at the exact revision above, matching Clang/LLVM 22.1.6 tools, and a new output directory. Capture does not fetch or rewrite source. The original VPATH Make route requires separate source/build/capture paths without whitespace or Make metacharacters.

olangc tools/ocore-runtime/c-compiler/chibicc.recipe.json --native-runtime \
  --native-runtime-source /absolute/clean/chibicc \
  --native-runtime-cc /absolute/llvm22/bin/clang \
  --native-runtime-cxx /absolute/llvm22/bin/clang++ \
  --native-runtime-llvm-nm /absolute/llvm22/bin/llvm-nm \
  --native-runtime-llvm-dis /absolute/llvm22/bin/llvm-dis \
  --native-runtime-jobs 2 --native-isa riscv64-unknown-none \
  --native-runtime-output obj \
  --llvm-library /absolute/llvm22/libLLVM.so.22.1 \
  --llvm-sha256 ACTUAL_VALIDATED_LIBRARY_SHA256 \
  -o /absolute/new/chibicc-product

The helper evaluates original Make variables in the source directory and preserves the complete source/object lists in the separate empty build. It records every Make producer and checks actual frontend arguments, source and object hashes, the final driver link, and its connected actual linker child records. Execute a C program through O-core

The opt-in language gate uses the same unchanged C fixture for a Clang reference object and LLVM IR. Its pointer, stack storage, loop, and non-inlined call pass through whole-module import and O-core assembly/object emission. An artifact-bound descriptive map is independently verified. The reference and owned objects are linked to the same static Linux syscall harness and must actually execute with positive and negative inputs on the current host.

OCORE_TEST_C_NATIVE=1 \
OCORE_TEST_LLVM22_BIN=/absolute/llvm22/bin \
OCORE_TEST_LLVM_LIBRARY=/absolute/llvm22/libLLVM.so.22.1 \
OCORE_TEST_LLVM_SHA256=ACTUAL_VALIDATED_LIBRARY_SHA256 \
OCOREC=/absolute/bin/ocorec \
python3 -m unittest discover -s tools/ocore-runtime/c-compiler \
  -p test_c_native_program.py -v

Provide an ELF ld.lld on PATH or with OCORE_TEST_LLD. Set OCORE_C_NATIVE_OUTPUT to an existing directory to retain exact source, IR, owned assembly/object/map, executables, commands, and hashes. The gate supports the current x86-64, AArch64, or RISC-V Linux host. These fixtures demonstrate the C language route and are separate from original compiler evidence.
