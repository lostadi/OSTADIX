## Implementation

- The ASI hook prepares replacement arguments separately from delegation.
  `AsiDelegation` invokes the original method outside the preparation exception
  handler, and its hook uses `PASSTHROUGH`. Original-method exceptions therefore
  do not cause a second delegation. Four success/failure combinations exercised
  the delegation helper; fatal preparation errors caused zero original calls.
- ASI provenance uses `Process.myUid()` and explicitly reports
  `caller_provenance=asi_process_local original_client_uid=unobserved`.
- The existing primary MCP operation was inspected through both its advertised
  `tools/list` schema and Rust handler. Only `source` is required. The existing
  ordinary `RuntimeRequest` path was retained. Lifted source now uses the
  engine's bundle classifier and existing project executor through that same
  operation, with host-owned staging, limits, deadline and cancellation.
- Ordinary and project results preserve the evidence each engine actually
  provides. Project null OIR/intent identities are not substituted with invented
  runtime identities. Lifted external bindings are rejected explicitly.
- A version/hash/signature-pinned hook extends the Google app's compiled legacy
  AppFunction schema inventory with the Ostadix schema. This is catalog
  augmentation, not proof of model selection or action execution.
- Android terminal version 11 routes its AppFunction through a private,
  certificate-pinned loopback HTTPS host to the installed MCP `o_execute`
  handler. It returns the handler's structured result and propagates
  cancellation. This adapter no longer uses the earlier JNI execution path.

## Unverified claims and remaining work

- Gemini has not been shown choosing Ostadix, generating the submitted program,
  invoking the primary MCP operation, or using its returned result.
- The Android AppFunction's connection to MCP has been demonstrated directly;
  a Nano-originated request through that connection has not been demonstrated.
- The catalog hook covers the legacy compiled schema map. Decompiled code also
  exposes a distinct V2 catalog with a conditional schema filter; its actual
  Ostadix entry reaching Gemini's model context remains unverified.
- General app control, unrestricted device actions, Gemini offline inference,
  and successful remote O-node execution have not been demonstrated.
- Process cleanup covers observed local descendants. It does not establish
  containment of deliberately daemonized or externally delegated work, nor
  rollback of effects already committed before cancellation.
- No end-to-end assistant latency or thermal benefit has been measured.

Google's [AppFunctions overview](https://developer.android.com/ai/appfunctions)
currently describes Gemini integration as a private preview. Its
[implementation guide](https://developer.android.com/ai/appfunctions/add-appfunctions)
distinguishes platform registration and direct command testing from an agent's
selection and invocation. These are relevant constraints, not evidence that a
particular account or server gate caused the observed missing dispatch.
