Attestation exclusion replay
----------------------------
TEESimulator-RS target.txt initially contained:
  com.android.vending
  com.google.android.aicore
  com.google.android.as
  com.google.android.as.oss
  com.google.android.gms
  com.google.android.googlequicksearchbox
  com.google.android.odad

The list was backed up to:
  /data/adb/tricky_store/target.txt.ostadix-pre-20260916

Those seven exact entries were removed and ASI, AS.OSS, AICore, and PSI were
restarted without clearing package data. PSI itself remained targeted. The
no-reboot retry still returned the same PERMISSION_DENIED response.

Later bytecode and live-log inspection proved that this was not a stock
attestation retry. TEESimulator reloads target.txt live, but its KeyMint handler
still intercepts requests with device-property attestation tags. AS.OSS sets
those tags while regenerating the fixed PcsAttestationKey alias for every
ProtectedDownload request. During the exclusion window:

  09-16 13:18:36.733 <AS.OSS> I ProtectedDownloadGrpcBindableService: Starting GetManifestConfig request
  09-16 13:18:37.338 <TEESimulator> I [TX_ID: 5290] Found generated response for PcsAttestationKey:
  09-16 13:18:37.445 <AS.OSS> E ProtectedDownloadGrpcBindableService: PERMISSION_DENIED

Android Keystore entry IDs and creation times for that alias changed across
requests, proving fresh regeneration rather than reuse of an August key. A
TEESimulator daemon restart changed its PID from 21097 to 31551, but the
unconditional device-property interception remained. The original target file
was restored byte-for-byte:

  0236bb20ffa7eb6d63e506d3e9cfacdf401669c7d8aabcb8a82da2e9cbaa5c18  target.txt
  0236bb20ffa7eb6d63e506d3e9cfacdf401669c7d8aabcb8a82da2e9cbaa5c18  target.txt.ostadix-pre-20260916

The supported clean retry requires disabling KernelSU module tricky_store and
a full reboot. No package data or keystore alias has been deleted.
