# O10 protocol implementation

Source: [O10 Governor Protocol and Hybrid O-kernel Specification](https://docs.google.com/document/d/1bV-tOFSrAZ9cAs0NkvHj2p79uLELqXZxQoOry6QNobk/edit), Draft 0, November 12, 2026.

This implementation includes the qualified M0 host control path and M1 resident monitor.
Qualification status and exact tool/source identities live in
`evidence/o10-m0-20261112/` and `evidence/o10-m1-20261113/`.
A milestone is accepted only after its complete
gate and regression set passes on one aligned build.

M0 passed its complete acceptance gate on the recorded AArch64 QEMU/TCG build.
[The acceptance receipt](../evidence/o10-m0-20261112/acceptance-r3d.json) binds
seven live checks, all six guest regression gates, 67 O10 component tests,
288 kernel unit tests and 261 source checks, with zero skips.

The hybrid target places mechanism in O-core at EL2, policy in a native EL1
Governor, and work in hosted kernels or lowered components. The governed
namespace and leases remain the service interface as backends move. M0 uses
the host runner as Governor; the native Governor follows in M5.

## Wire

Frames use little-endian size[4], type[1], tag[2]. Requests other than Tversion
carry epoch[8], seq[8]. The wire version is eight bytes, `O10\0\0\0\0\0`.
`scripts/o10.py` defines the complete Draft 0 catalog and strict field bounds.
`ocore/runtime/common/o10_codec.oc` implements native validation and byte access.
Rlstat records are opaque because Draft 0 leaves their fixed layout open.

## Synchronous M0 journal

O-core retains 256 full request/reply pairs, each using two 64-byte slots.
Only the host-private control transport dispatches these operations.
Valid mutating requests take the next global sequence. An identical whole
frame, including its tag and epoch, receives the retained reply before epoch
validation. A different frame under a used sequence, or a gap, returns ESEQ.
An evicted sequence cannot be replayed. Toutcome reports OUT_OF_WINDOW for it.

Tclaim's header carries the current epoch; its body compares expected epoch
and selects a strictly larger new epoch. The first claim uses epoch zero and
sequence one. Valid platform errors consume a sequence and are journaled;
framing, stale-header-epoch and sequencing rejections leave the log unchanged.
A failed claim whose header epoch is current is journaled too.
The provisional minimum msize is 78, sufficient for the maximum retained
outcome envelope. Read-only requests use seq zero and the current epoch.

These rules make Draft 0's retry and first-claim details explicit for M0.
Asynchronous mutation reservation and Governor takeover remain an M5 design
dependency; the current executor commits synchronously before acknowledging
the mailbox.

## Host transport and lifecycle

The operation-10 submission frame occupies `0x6d0a0000..0x6d0a01ff`; the
completion frame occupies `0x6d0a0200..0x6d0a03ff`. Both ranges lie outside the
Linux and Plan 9 stage-2 RAM mappings. O-core publishes completion before the
mailbox acknowledgement at `0x6d000080`. The runner writes only the submission
range while QEMU's CPU is stopped.

Tversion, Tclaim and Toutcome execute in the common journal. Tstat observes
either existing domain, including generation, instance, counters and state.
Twithdraw, Trestore and Tbind operate on the existing Plan 9 recovery path.
M0 image handles 1 and 2 name the boot-registered immutable Plan 9 kernel and
DTB copies. Initial domain generations and grant-4 generation are one.
Twithdraw and fault containment revoke the transport; Trestore issues a new
domain generation. Tbind accepts the current grant-4 generation and Plan 9's
current transport generation, clears old fids and opens a new session.
The restored domain waits in BLOCKED until Tbind supplies its namespace
transport. This prevents the new kernel from touching a revoked UART before
the host can bind it.

Provisional numeric enums match `PROVISIONAL_*` in the Python codec:
domain kinds GOVERNOR=1, GUEST_KERNEL=2, NATIVE_SERVICE=3; domain states EMPTY=0,
PROVISIONED=1, RUNNING=2, BLOCKED=3, FAULTED=4, WITHDRAWN=5.
Session reply handles use a monotonic session generation in the upper 32 bits
and grant slot 4 in the lower 32 bits. Generation exhaustion fails closed.

The profile advertises its O10 addresses and version. Its recovery runner uses
O10 by default. Legacy operations 1 and 2 are available for a separate rollback
boot, before an O10 claim; operation 3 continues to carry coordinator service
traffic until M6. Linux lifecycle and additional domain creation follow M2/M3.
Unsupported operations return EUNSUPPORTED.

## M1 resident monitor — qualified Draft 0 gate

M1 passed `verify_o10_m1.py --acceptance-scope draft0` on the exact R7
build captured in [the acceptance receipt](../evidence/o10-m1-20261113/acceptance-draft0-r7.json).
The live test kept both guests stopped while answering 182 observations over
60.24 seconds, then restored the original Plan 9 provider. All six guest
regression gates, 147 O10 component tests, 288 kernel unit tests, 74 targeted
tests and 261 language-source checks passed with zero skips. The classified
paths use 124 native host register-model scenarios; four separate targeted
checks execute the EL2 context under QEMU.

The recorded source and MCP release is `cb53ca51c5e8ef3e4692870640d71935a82556fa`
with the captured helper/test hashes. The monitor ELF SHA-256 is
`d8163b97dd9b7c165d7daa761756bb11fa164338598efd899c8b3c0f82927d32`;
its profile SHA-256 is
`4ed18d420aa3f0348d324f4e0d8f38854222eb7faa67b0dce338322313701938`.
The scope is AArch64 QEMU/TCG on X12. The additional guest-MMIO probe remains
unqualified; its failed receipt is retained, and default `extended` acceptance
still requires it to pass. The explicit Draft 0 contract follows the original
M1 resident, classified-path and regression requirements.

The monitor keeps the existing EL2 saved-context continuation resident even
when both guest LIVE bits are clear. The monitor releases its busy word before
a bounded WFI, claims and acknowledges the physical timer on wake, then marks
itself busy before polling the host mailbox, mediated I/O, and guest wakeups.
The 5 ms physical polling bound remains; earlier unmasked guest timers may
shorten it. No EL1 context is restored until the scheduler has a runnable
domain. A restored Plan 9 remains parked until its namespace bind completes.

An explicit `--o10-qualification` build sets the generated
`kernel_world_profile::O10_QUALIFICATION` constant to 1 and records
`o10_qualification: true` in the monitor manifest. Its host-private O10 shim
admits `Tinject` fault 1, which contains only the named, generation-checked
live domain. The production constant defaults to 0 and every injection
returns EUNSUPPORTED. Unsupported fault numbers also return EUNSUPPORTED.
This operation changes lifecycle/lease state; it does not damage guest RAM
to approximate a fault. Linux containment revokes its namespace session and
stops scheduling/polling its frontends; Linux restore remains an M2 task.

Scheduler MAX classification:

| Existing source path | M1 treatment |
| --- | --- |
| O10 invalid domain slot or generation | Ordinary ESTALE sentinel, never a scheduler return |
| Invalid current domain | Internal diagnostic 0x1101; assembly checks before context pointer arithmetic |
| Unexpected real IRQ in dispatch or idle | Internal physical-routing diagnostic 0x1102 |
| No runnable domain | Continue the resident EL2 idle loop |
| Failed vGIC poll/wake validation | Internal saved-bank diagnostic 0x1103 |
| Impossible non-runnable selected result | Internal scheduler diagnostic 0x1104 |
| Disabled/masked timer deadline MAX | Ordinary no-deadline sentinel |
| PSCI unsupported result MAX | Guest-visible result, not a monitor halt |

The current vGIC poll failure paths indicate native saved-LR ownership,
duplicate-LR, or bank-capacity corruption. Unsupported guest MMIO follows
the separate guest containment path. An unsupported lower AArch32
synchronous entry now saves the complete context before containment and
rescheduling. Same-EL exceptions and unclassified physical FIQ/SError remain
fail-closed internal faults; this change does not claim recovery from
unattributable asynchronous hardware failures.

Internal failures publish reason and three arguments at host-private
0x6d0000d0..0x6d0000ef, print `KW unified internal invariant:` directly to
the physical serial output, and halt. Direct serial output avoids recursion
if the Linux output counter is itself corrupt. Additional reasons are
0x1100 (unexpected native vector), 0x1105 (output counter exhaustion),
0x1106 (lease generation exhaustion), 0x1107 (journal commit failure), and
0x1108 (assembly helper/configuration contract; original arguments and return
address are recorded). The unsupported-EL boot guard runs before a valid
EL2 stack exists and retains its bare halt.

`scripts/verify_o10_resident.py` always forks a new private state, requires a
qualification/recovery/provider build, faults Linux, withdraws Plan 9, polls
both through Tstat for at least 60 seconds with zero live guests, then
restores Plan 9 and checks its fresh original provider marker. It records
the source/build/tool identities, QEMU invocation, samples, and result JSON.
The final acceptance verifier binds aligned MCP provenance, classified-path
tests and the full same-build regression set to the captured build.

The canonical dispatcher exposes the owning scripts without changing their
arguments: `o kernel unified-build --help` lists `--o10-qualification`, and
`o kernel o10-resident --help` lists the resident gate's required state,
build, evidence session, and MCP-release inputs.


Unified Linux MMIO and periodic
backend polling use `kw_handle_exit_checked`, which returns 0 (accepted),
2 (guest rejection), or 3 (internal backend failure). The unified scheduler
contains Linux for malformed guest MMIO or rejected guest queues, revokes
its namespace session, and continues the survivor. A failed native namespace
store or outer network driver uses diagnostic 0x1109, with the component's
failure code and detail; it does not attribute native corruption to a guest.
The finite standalone kernel-world handler retains its own qualification
policy and is not called by unified dispatch.

Unified HVC/SMC dispatch rejects nonzero immediates and calls outside the PSCI
function namespace through domain containment. PSCI SYSTEM_OFF remains an
explicit error result and cannot halt O-core. The final R7 build and same-build gates cover these changes. Earlier receipts
retain their recorded source snapshots and outcomes.


Each frontend exposes a trusted
`fault_kind`: 0 for usable state, 2 for guest queue/protocol rejection, and 3
for an unprovisioned or internally failed lifecycle/reset state. Namespace
session-reset failures (including generation exhaustion) and an impossible
persistent held block request now produce an internal diagnostic. The checked
poll path validates trusted state before invoking queue work; finite standalone
withdrawal behavior is unchanged.

The checked Linux console admits DR, RSR/ECR, FR, ILPR disabled, baud/configuration
latches, 8N1 LCR with FIFO on/off, CR without IrDA/loopback/hardware flow control,
the qualified IFLS setup, IMSC/RIS/MIS/ICR and the eight identification words.
ICR accepts the normal all-ones clear after masking the decoded access width;
only the defined 0x7ff bits affect virtual state.
DMA control is readable as disabled and writable only as zero. Reserved
locations, writes to read-only/ID registers, reads of ICR, DMA enable and
off-corpus serial modes reject the guest explicitly. Baud and configuration
readback are virtual-console state; physical baud timing, FIFO threshold
timing, modem signalling, error injection and complete PL011 compatibility are
not qualified. The register map comes from
[ARM DDI0183G section3.2](https://documentation-service.arm.com/static/5e8e36c2fd977155116a90b5?token=).
