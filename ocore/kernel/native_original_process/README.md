# Original process-component native integration

This isolated profile executes unchanged original musl `getuid` and `_Exit`
USER functions through the existing native O-core credential-read and sole-task
exit services. It is a bounded application-component execution milestone,
not a complete musl/CRT, arbitrary Linux application, general Linux provider,
interactive OS, hardware-driver or efficiency claim.

`verify.py` requires the complete original two-source compiler-owned recipe
and a successful detached source-group/body readmission. The earlier optimized
`_Exit` attribute failure is preserved. A separately staged typed-range compiler
candidate now imports both units and completes fresh readmission on all three
source ISAs; its wider compiler qualification is a separate gate. An incomplete or
one-unit group is refused before kernel compilation or VM launch. Original
Clang reference objects never qualify as lowered implementations and are never
linked into the native kernel.

The separate USER ELF links the actual reopened O-core objects, an explicitly
authored invocation/control bootstrap and entry assembly. It keeps both
allocated `.note.ocore.platform` records in a read-only, nonexecutable PT_LOAD
and read-only PT_NOTE. Their exact descriptor bytes, static required syscall
sets/arities, object identities, original function bytes and final symbols are
checked. The existing loader accepts this layout unchanged; the isolated
trusted packaging gate supplies the provider binding. General untrusted note
admission in an application launcher is not implemented here. The kernel ELF
links only native O-core and its separately admitted kernel-safe original-codec
closure. USER objects/notes are never routed into that codec closure or CPL0.

The selected native x86 profile is one serialized boot CPU, four already
admitted loaded Linux sole-task/sole-mm principals, fixed GS-selector zero and
integer-only execution. Trusted boot admits actual host uid/euid/gid/egid for
every principal and the same values in initial auxv. Numeric credentials grant
no native resource or filesystem authority. The component's actual static
provider is getuid102/arity0 and exit60/exit_group231/arity1. Authored private
synchronization/file controls are a separate test interface. They are not an
extension of the original component or a general Linux ABI.

Each original getuid syscall must originate at the actual decoded final USER
function's SYSCALL site; its result is supplied by the generation-bound native
credential service. Original `_Exit` calls must likewise originate at one of
its two decoded post-SYSCALL PCs. Their numbers and counts are observed from
the real guarded kernel entry frame, not trusted from guest output. The normal
profile terminates through231. A separate, declared-before-run provider profile
withholds231 with actual `-ENOSYS`, allowing the unchanged original loop to
reach60. No fallback body is authored or substituted.

Four fresh isolated native boots check two C-int status groups, including0/1/42/255,
256/-1/INT_MAX/INT_MIN, exact Linux wait-word encoding, surviving principals'
continued native file access/getuid, owner-only descriptor cleanup and no
resumed exit frame. After the last original exit, the existing production
scheduler must remain in its dedicated management HLT with IF set, correct
CR3/GS/FS/stack and live timer progress. Focused implementation/service proofs
remain distinct from this original-component gate; this is not a claim of complete platform/provider admission.

`reference.py` independently exercises the original Makefile-produced x86
Linux objects. Only its owned child installs NO_NEW_PRIVS and an exact x86
seccomp231→ENOSYS filter; parent credentials/global filters remain untouched.
`strace -D` keeps that source child directly waitable. PID/PPID, raw waitpid
words, exact binary UID telemetry and actual original function syscall PCs are
checked. Normal reference and fallback are real Linux executions, not compiler
or native O-core acceptance. Other-ISA fallback remains unqualified unless
actually exercised under a declared supported mechanism.

`test_native_original_process_artifacts.py` uses an explicitly supplied,
already qualified one-unit USER getuid object for note/linker boundary controls
only. Its generated entry is never executed. The tests reject missing or
writable PT_NOTE, writable note LOAD, wrong note owner, truncated descriptor and
one-unit-as-two-unit admission. These tests do not qualify the original two-unit
component. Missing external profile inputs are explicit skips outside the
selected gate; a selected qualification must record all controls and zero skips.

The native returning getuid call's opaque-provider FENV/control/sticky-state
contract is explicitly UNMET. Integer-only source/instruction audit is not a
floating-state preservation proof. The source artifact platform/resource/runtime
completeness flags remain false even after these workload executions. The
terminal `_Exit` path has no returning floating-state claim.

Shared-mm clearing/waking, clone, futexes, wait/signals, credential setters,
FPU/thread isolation, asynchronous GS-selector isolation, SMP, other-ISA native
kernel providers, a full C runtime/initialization closure and a usable OS remain
separate unmet work. No default images, running VM, saved head or Mode26 proof
is changed by this private profile.

`compare_users.py` is an additive external Linux/reference comparison helper,
with actual per-ISA recipes/headers and no foreign fallback claim. Its original
component function bytes, notes and actual static syscall sets are bound. For
foreign ELF functions carrying input text relocations, raw pre/post-link bytes
are recorded separately; they are not normalized or called identical. Functions
without such relocations must remain byte-identical. External original `_Exit`
status/FENV cohorts may be qualified by the compiler prerequisite packet; this
helper has no execution claim until it is actually run.
