O10 Governor Protocol and Hybrid O-kernel Specification
Nov 12, 2026 · @Lee Daghlar Ostadi
1. Purpose, status and naming
O10 is the protocol a Governor uses to control O-core: it creates and replaces kernel domains, and mints and revokes the leases they hold. This spec defines O10 and the hybrid O-kernel it governs, so agents can build both, milestone by milestone, through the Ostadix MCP.
Status. Draft 0, for Lee's review. It is a proposal derived from a source read of OSTADIX-master on 2026-11-11. Nothing was executed for it, and nothing in it is claimed until its gate in §9 passes.
Who reads what.
Lee: §2 (baseline), §3 (target architecture) and §11 (open decisions).
Implementing agents: §4 (invariants), §5 to §8 (design), §9 (milestones and gates) and §10 (operating rules).
Scope. In scope: the AArch64 unified world (one EL2 monitor hosting whole kernels), its path to the hybrid end state, and the O10 protocol. Out of scope: the hosted OIR/HGraph pipeline, the x86-64 personality modes (except the lease core reused in §5), and multi-node replication of the Governor (§11).
Normative words. MUST, MUST NOT, SHOULD and MAY carry their RFC 2119 meanings.
Naming.
O10, read "O-ten": a capital O, then the number 10. It is the step after 9P: 9P moves bytes inside an authority, and O10 moves authority.
Wire version string: O10, in an 8-byte ASCII field padded with zero bytes. Later revisions are O10.1, O10.2, and so on.
Messages follow 9P's convention: a T-message is a request, and its R-message is the reply, matched by tag (Tclaim and Rclaim).
Code spelling is o10, since identifiers start with a letter: ocore/runtime/common/o10_codec.oc, scripts/o10.py, constants O10_*.
Type codes are 160 to 199, disjoint from every code used by 9P2000, 9P2000.u and 9P2000.L.
The Governor rings O-core's doorbell with HVC #10.

Today the unified world runs unmodified Linux and 9front side by side under one O-core EL2 monitor, and it replaces Plan 9 cleanly. Linux cannot yet be replaced, authority is hardcoded, and the Governor runs on the host. Everything below was read in source, not executed.

What it lacks
Each gap has an ID that a milestone in §9 closes.
G1. O-core has no life of its own. It runs only when a guest traps into it. With zero runnable guests, uw_handle_exit returns MAX and the monitor halts.
G2. Linux is not replaceable. Withdraw (op 1) and inject (op 3) both require LIVE[0] == 1, restore (op 2) rebuilds only Plan 9, and no operation resets Linux. docs/OKERNEL_UNIFIED.md records that severe Linux failures can stop the whole supervisor.
G3. The Governor runs outside the machine. native_control in scripts/okernel_unified_world.py (line 369) pauses the CPU through QEMU and writes the mailbox at 0x6d000070. A real board has no host.
G4. Authority is hardcoded. namespace_store.oc has five fixed grant slots whose rights come from root_for and writable (lines 141–142). Linux and Plan 9 both hold root read-write over the whole store, with no attenuation, derivation or device leases.
G5. Exactly two domains. The scheduler picks domain ^ 1, and per-domain state lives in two-element arrays.
G6. Control and service traffic share one mailbox. Ops 1 and 2 are lifecycle control. Op 2's bootstrap text and op 3's coordinator payload are service traffic for Plan 9's console and Linux's p9 client.
G7. The Plan 9 transport is slow. 9P over an emulated UART costs a trap per register access. docs/OKERNEL_UNIFIED.md reports 9.72 to 15.51 s to first output for p9 echo under TCG; how much of that is the transport is unmeasured.
3. Target architecture
The end state is hybrid: a component is absorbed into O-core when its source and interface allow it, and hosted inside a whole guest kernel when they don't. The governed namespace and its leases are the one interface that stays fixed while components move between the two.
O10 architecture · three layers, two protocols
Only the Governor holds the O10 channel to O-core, while guests reach shared objects through 9P on transports bound to their leases. Until M5, the host runner plays the Governor through the stopped-CPU mailbox.
Three layers
L0, O-core at EL2: mechanism. It owns stage-2 tables, VMIDs, the vGIC, the scheduler, the lease table, the O10 executor with its outcome journal, and mediated devices. It holds exactly one built-in policy: the Governor exists (§7).
L1, the Governor, a native EL1 domain: policy. It decides which domains run, which leases they hold, and when they are replaced. It is the only party that speaks O10.
L2, broker domains: work. These are whole guest kernels (Linux, 9front, later XNU) and native components lowered from original source. Each holds leases and exports services into the governed namespace.
Two protocols
O10 moves authority: domain lifecycle, minting, deriving, binding and revoking leases, quiesce requests, and fault events.
9P moves bytes inside authority. Every guest reaches the namespace store through a transport bound to a namespace lease. As today, the transport supplies the authority; no attach name, path or fid confers it.

Migrating without breaking clients
A service moves from hosted to lowered behind the same namespace path and lease kind. The Governor mints a lease for the new backend, runs the service's conformance corpus against both backends, then revokes the old lease and rebinds. Clients see at most one ESTALE on fids they held, and walk again.
This is a strangler-fig migration: the old system keeps serving until each piece is replaced. It reconciles the current documents. The multikernel is the migration path and the permanent home for closed kernels; the unified native OS is where open components end up.

4. Normative invariants
Every milestone MUST preserve all fifteen invariants. A gate that passes while breaking one has not passed.
I1. Authority comes from the transport. No O10 or 9P field that names a domain, lease, object, path or fid confers authority. Authority is the lease bound to the transport a message arrived on, limited by that lease's rights.
I2. One writer of mechanism state. Only O-core changes the domain table, lease table, stage-2 tables, IRQ routes and device state. The Governor requests changes through O10; guests never do.
I3. Generations everywhere. Every reference to a domain, lease, session or namespace object carries a generation, and a mismatch fails with ESTALE. Generations never decrease, and no (slot, generation) pair is issued twice.
I4. Mechanism operations apply exactly once. Each mutating O10 request carries (epoch, seq), and O-core journals its outcome. A retransmitted identical request gets the journaled reply; a different body under the same seq fails with ESEQ.
I5. Service operations apply at most once. Guest-level work whose completion is unknown, such as a p9 command, stays unknown and is never replayed automatically. This keeps the current p9 protocol's semantics.
I6. One revocation shape. A lease has one holder and a bounded set of dependents. Revoking it first invalidates the holder's handle, then ends every dependent, and frees the slot only after all dependents are released.
I7. Leases are nontransferable by default. Domains cannot delegate leases. Only the Governor derives a lease, only by narrowing it, and derivation depth is at most 2 in draft 0.
I8. Lifecycle is symmetric. Every domain kind, Linux included, can be withdrawn, restored and destroyed. No O10 operation is gated on a particular guest being alive.
I9. O-core is resident. The monitor never halts because no guest is runnable. It halts only when its own internal invariant is violated, and then with a diagnostic.
I10. One built-in policy. O-core's only compiled-in policy is to keep the Governor domain alive, respawning it from its immutable image. Every other decision belongs to the Governor.
I11. Fail closed. Unsupported or off-corpus behavior returns an explicit error. Silent no-ops and dummy functions are forbidden; a sentinel MUST trap with a documented error code.
I12. Replacement is clean. Withdraw and restore zero private RAM, reset architectural and interrupt state, and invalidate the domain's VMID TLB entries without touching any survivor's state.
I13. No unconfined guest DMA. A guest programs DMA only for a passthrough device behind an IOMMU that has passed its confinement gate (§8). Mediated devices copy through monitor-owned buffers, as they do today.
I14. Ledger entries are names. Entries in the Governor's log are names and generations, never bearer authority, as ocore/world/identity.oc already defines.
I15. Claims stay inside their gates. Every claim names the gate that proves it and that gate's scope. QEMU is not physical hardware, and hosted is not lowered.

Derivation
Only the Governor derives, with Tderive. A derived lease's rights MUST be a subset of its parent's, and its object MUST lie inside the parent's scope: the same root or a descendant for NAMESPACE, a subrange for MEMORY, the same device for DEVICE. Its depth is the parent's plus one, at most 2, and it is registered as a dependent of the parent. Its holder may differ from the parent's.
Binding
A NAMESPACE or CONSOLE lease is used through exactly one transport at a time. Tbind attaches it to a transport owned by the lease's holder and opens a session with a fresh generation, the job session_init does today. Fids opened in that session are the lease's dependents, and rebinding clears them, as session_init already does.
Revocation
Trevoke runs in this order, mirroring the revocation path in delegated_resource.oc:
Check the handle's generation. A stale handle fails with ESTALE, which subsumes today's revoke_if_current.
Advance the lease's generation and publish REVOKED, so any concurrent use fails.
Revoke derived leases, close bound sessions and clear their fids, revoke memory views, and detach mediated device frontends.
Retire the slot once every dependent count reaches zero. Only then may the slot be reissued, under a higher generation.
Withdrawing or restoring a domain revokes every lease it holds (§7).

Behavior-preserving migration
M4 first re-creates the four live grants as leases with exactly the roots and rights that root_for and writable compute today. Grants 1 and 4 get object 1, read-write; grant 2 gets object 2, read-write; grant 3 gets object 2, read-only. Every existing gate MUST pass on that build before any lease is narrowed, and narrowing follows the policy Lee sets (§11).
The two architectures share semantics before they share code. M4 runs one lease conformance corpus against both the x86-64 delegated-resource implementation and the AArch64 lease table. Merging them into one module is optional until both pass.
6. The O10 protocol
O10 is a small binary request-reply protocol framed exactly like 9P. Every mutating request carries the Governor's epoch and a sequence number, and O-core journals each outcome, so a request applies exactly once.
Framing
Every message starts with size[4] type[1] tag[2], little-endian, where size counts itself. That is 9P2000's header, so existing 9P framing code can be reused. Every T-message except Tversion then carries epoch[8] seq[8]; read-only requests send seq 0.
All fields are fixed-width little-endian integers, and no strings cross the EL2 boundary. The default msize is 512 bytes, negotiated down by Tversion.

Epochs and sequence numbers
The epoch is GovernorTerm and the seq is GovernorLogIndex, both from ocore/world/identity.oc.
Tclaim makes a Governor current. Its new epoch MUST exceed the current one, and its expected epoch MUST equal the current one (0 when no Governor holds it). That is the compare rule session_claim already uses.
The seq is global across epochs. A new Governor continues at the last applied seq plus one, which Rclaim reports, the way a Raft log index continues across terms.
O-core rejects a stale epoch with ENOTCURRENT, and a gap or a reused seq with a different body with ESEQ. An identical retransmission gets the journaled reply.
The journal keeps the last 256 outcomes, each with full request and reply bytes. Every mutating message fits in 64 bytes, so the journal is 32 KiB. Toutcome answers for any seq in that window.
Transport
Native, from M5. Two monitor-owned pages are mapped only into the Governor domain's stage-2: a submission ring and a completion ring of msize slots. The Governor rings with HVC #10. Fast operations complete inside that trap; Trestore, cooperative Tquiesce and Twait complete later and raise a virtual interrupt on the Governor.
Host shim, M0 to M4. The existing stopped-CPU mailbox carries O10 frames. The host writes a frame into a new host-private region, writes operation code 10 to the mailbox at 0x6d000070, and O-core acknowledges at 0x6d000080 after writing the reply. The agent picks the region's addresses; they MUST lie outside every guest's stage-2 mapping, and MUST be added to the memory-map comment in unified_world.oc and to write_native's allowed ranges.
One Governor at a time. From M5, the host shim accepts only read-only messages (Tversion, Tstat, Tlstat, Toutcome, Twait), plus Tinject in qualification builds.

7. Domains and lifecycle
Every domain, Linux included, follows one lifecycle, and O-core keeps running when none of them is runnable. The only domain O-core restarts on its own is the Governor.
domain lifecycle · 6 states
Restore works from FAULTED or WITHDRAWN and always issues a new generation. Entering either stopped state revokes every lease the domain holds.

Transitions
EMPTY becomes PROVISIONED on Tcreate, and PROVISIONED becomes RUNNING on Tstart.
RUNNING and BLOCKED alternate as the guest waits (WFI) and wakes on its timer or a routed interrupt.
RUNNING or BLOCKED becomes FAULTED when contain() rejects an exit. O-core emits DOMAIN_FAULT and revokes the domain's leases at once, as it already revokes Plan 9's wire.
RUNNING, BLOCKED or FAULTED becomes WITHDRAWN on Twithdraw.
FAULTED or WITHDRAWN becomes RUNNING on Trestore, under a new generation.
Any state but EMPTY becomes EMPTY on Tdestroy.
Any other transition fails with ESTATE.
Scheduling
O-core runs RUNNING domains round-robin on the existing 10 ms EL2 timer quantum. A Governor with a pending virtual interrupt runs next. BLOCKED domains wake as they do today.
Resident O-core
When no domain is runnable, O-core idles in its own EL2 context. It services the host shim or the Governor's rings, the EL2 timer and wake events, and never returns MAX for this reason (closes G1).
Every existing MAX return in uw_handle_exit and the idle path gets classified. A guest-attributable cause contains that domain and continues; a cause internal to O-core halts with a diagnostic (I9).
Example: today a vGIC poll failure for one domain both contains it and halts the monitor. After M1 it halts only if the cause is internal to O-core.
The Governor's lifecycle
O-core creates the Governor at boot from its immutable image, before any guest. It is the only domain with an O10 ring.
If the Governor faults or exits, O-core zeroes and reloads it under a new generation and emits GOVERNOR_RESPAWNED. That is O-core's single built-in policy (I10).
While no Governor holds a claim, guests keep running under their existing leases. Nothing is minted or revoked except by the fault cascade, and events accumulate. Liveness degrades; safety holds.
The Governor keeps its durable state in the namespace store, under a lease only it holds.
A respawned Governor sends Tversion, then Tclaim with the old epoch as expected, then Toutcome for any seq it had in flight, then Twait from its last saved cursor.
Withdrawing and restoring Linux
Linux gets the same treatment Plan 9 gets today (closes G2):
Twithdraw stops scheduling Linux and revokes its namespace lease, which closes the virtio-9P session and clears its fids. It detaches the virtio-blk and virtio-net frontends and routes Linux's interrupts off.
Trestore zeroes Linux's private RAM and reloads its kernel and initramfs from immutable copies. It resets vCPU, vGIC and VMID TLB entries, and resets every virtio transport under a new generation.
The Governor rebinds leases with Tbind. The package disk keeps whatever the dead kernel wrote, and ext4's journal recovers it on the next mount.
Until M6 moves the console out of Linux, the operator's Linux shell ends with Linux.

Passthrough requirements
O-core programs the SMMU, Arm's IOMMU, so the device's stream ID translates through the same IPA-to-PA map as its holder's stage-2.
Before any guest gets the DMA right, a hostile-DMA gate MUST pass. The guest programs the device to write outside its own RAM, the SMMU faults, the domain is contained, and a checksum of O-core's memory is unchanged.
The development target is QEMU's virt machine with an emulated SMMUv3 (-machine virt,iommu=smmuv3) and a PCIe device behind it. The agent MUST confirm that the installed QEMU emulates SMMU stage-2 translation before relying on it.
Real boards need their own evidence. Any DMA master an SoC does not place behind an SMMU cannot be passed through (I13).
Lowered drivers
Genode's DDE Linux runs Linux drivers outside Linux by emulating the kernel APIs they call, and its porting work leans on dummy functions. O10's lowered mode keeps the approach but replaces dummies with evidence:
Measure the driver's closure: every Linux kernel symbol it reaches, from its Kbuild graph.
Implement each symbol natively, or install a sentinel that traps with a documented error (I11).
Prove every sentinel unreachable on the driver's qualified corpus with coverage traces. A sentinel reached off the corpus fails closed.
This applies the rule already in §6 of MULTIKERNEL_PERSONALITY_PROPOSAL.md: off-corpus behavior fails closed with the documented error.
Choosing a mode
Mediated when O-core already drives the device, or isolation matters more than throughput.
Passthrough when only the hosted kernel's driver can run the device and the SoC's SMMU covers it.
Lowered when the driver's closure is affordable and the device should survive a restart of the hosted kernel.
9. Milestones and acceptance gates
Eleven milestones take the system from today's experiment to the hybrid end state. M0 to M6 make every kernel disposable under a native Governor; M7 to M10 add passthrough and lowered devices, a faster Plan 9 transport, and the XNU path. Each milestone passes only when its gate and the full regression set pass on the same build.
milestone roadmap · M0 to M10
M2 and M5 together unlock M6, after which no kernel is special. M4's leases gate every device milestone, and M10 can start once M3 hosts a third domain.
Regression set
These run at every milestone: scripts/verify_okernel_two_domains.py, verify_okernel_unified_recovery.py, verify_okernel_unified_client.py, verify_okernel_unified_provider.py, verify_okernel_unified_runtime.py, verify_okernel_p9_default_compile.py, tests/test_okernel_*.py and scripts/check_language_sources.py. As the repo already states, a skip does not qualify.
M0. O10 wire and host shim
Closes G6.
Build: scripts/o10.py, a reference codec for every message in §6, and ocore/runtime/common/o10_codec.oc, the native codec. The O-core executor handles Tversion, Tclaim, Toutcome, Tstat, Twithdraw, Trestore and Tbind on the host-shim transport, with the 256-entry journal. Until M4, the lease handle in Tbind names one of today's grants, as (generation << 32) | grant slot.
Build: okernel_unified_world.py issues ops 1 and 2 as O10 messages through mailbox operation 10. The old op codes stay for one milestone as a rollback path, then fail with EUNSUPPORTED from M2.
Build: with Lee's approval recorded, amend the end-state statements in docs/OKERNEL_UNIFIED_IMPLEMENTATION.md to reference this spec.
Gate, tests/test_o10_codec.py and scripts/verify_o10_journal.py:
Every message round-trips byte-for-byte between the Python and native codecs, run in the native test harness the way namespace_store.oc is tested today.
Malformed sizes, unknown types and 9P type codes fail with EBADMSG.
An identical retransmission returns the journaled reply byte-for-byte. A reused seq with a different body fails with ESEQ, as does a gap, and a stale epoch fails with ENOTCURRENT.
The regression set passes with the runner speaking O10.
M1. Resident O-core
Closes G1.
Build: an EL2 idle context that services the shim mailbox with zero runnable domains, and a classification of every MAX return (§7).
Build: Twithdraw on Plan 9 no longer requires Linux to be alive, and Tinject exists in qualification builds.
Gate, scripts/verify_o10_resident.py:
Tinject faults Linux, then Twithdraw withdraws Plan 9. Tstat confirms neither is runnable, and the monitor keeps answering Tstat for 60 s.
Trestore brings Plan 9 back, and its provider ready marker validates.
Each reclassified MAX path has a test showing it contains and continues, or halts with a diagnostic, as classified.
M2. Linux disposable
Closes G2.
Build: symmetric Twithdraw and Trestore for Linux (§7), with immutable copies of the Linux kernel and initramfs outside guest mappings. Virtio transports reset under new generations. Runner policy: restore Linux after a fault.
Gate, scripts/verify_o10_linux_restart.py:
Throughout the test, Plan 9 runs a loop appending a counter to a file in its own namespace subtree.
Tinject faults Linux while it is writing a 64 MiB file to the package disk and partway through an apk add of a declared package.
Trestore and Tbind bring Linux back. fsck.ext4 -n reports clean after journal replay, and the APK database opens and checks clean; the agent records the exact commands and output.
Fids Linux held before the fault fail with ESTALE at the store. Plan 9's session generation and fids are unchanged, and the agent records the largest gap in its counter.
M3. N domains
Closes G5.
Build: the 8-entry domain table, round-robin scheduling, per-transport interrupt routes, and Tcreate, Tstart and Tdestroy.
Gate, scripts/verify_o10_three_domains.py:
Three guests run at once, each with its own namespace grant from today's table: Linux, 9front, and either a second 9front or a minimal native test domain.
Tinject faults each in turn; the other two keep running, and each is restored.
Tdestroy then Tcreate reuses a slot under a higher generation, and every old handle fails with ESTALE.
M4. Leases
Closes G4.
Build: the AArch64 lease table with Tlease, Tderive, Trevoke and Tlstat. The namespace store checks every fid operation against its lease's root and rights instead of root_for and writable.
Build: boot leases that reproduce today's grants exactly (§5), plus one lease conformance corpus run against both the x86-64 delegated-resource code and the AArch64 lease table.
Gate, scripts/verify_o10_leases.py:
The behavior-preserving build passes the regression set.
On a narrowed build, Linux holds read-write on one subtree only. A write outside it fails, and Plan 9 is unaffected.
Trevoke on Linux's lease makes its fids fail, leaves Plan 9's session and fids unchanged, and its counts match the fids that were open.
A derived lease dies with its parent, a stale handle fails with ESTALE, and a depth-3 derivation fails with EDENIED.
The conformance corpus passes on both architectures.
M5. Native Governor
Closes G3.
Build: the Governor as a native EL1 domain carrying the runner's policy: watching the provider, recycling Plan 9, restoring Linux. It gets its O10 rings, the HVC #10 doorbell, O-core's respawn rule, and a namespace lease for its durable state. The host shim becomes read-only, plus Tinject.
Gate, scripts/verify_o10_governor_respawn.py:
With the host only observing, a Plan 9 recycle triggered as in verify_okernel_unified_recovery.py completes under the native Governor.
Tinject faults the Governor in the middle of a Plan 9 Trestore. Guests keep running: the Linux shell's PID and start time are unchanged, and Plan 9's counter advances.
O-core respawns the Governor and emits GOVERNOR_RESPAWNED. Tclaim succeeds only with the right expected epoch, and a message under the old epoch fails with ENOTCURRENT.
Toutcome on the in-flight seq returns APPLIED_OK or NOT_APPLIED, never anything ambiguous, and Plan 9 ends RUNNING.
M6. Console and acknowledgements out of Linux
Build: a native console service holding a CONSOLE lease, built on the existing EL2 console switcher.
Build: recovery acknowledgements published in a namespace subtree that only the Governor's lease can write and that guests can only read. Linux's p9 client reads them there, and op 3 and the Linux-only coordinator UART are retired. Once leases make that subtree Governor-only, text in it is evidence, so the reason for the Linux-only UART is gone.
Gate:
Linux restarts by the M2 procedure while the operator stays attached to the native console, and the session survives.
Linux's p9 client reads an acknowledgement the Governor wrote, and any guest write to that subtree fails.
M7. First passthrough device
Build: SMMU stream-table management in O-core, DEVICE leases in PASSTHROUGH mode, and enforced reset classes, developed on QEMU virt with the emulated SMMUv3 (§8).
Gate:
Linux drives a passed-through PCIe device with its own driver.
The hostile-DMA test in §8 passes.
When Linux is withdrawn, Tquiesce returns the state its reset class predicts. The device is then leased to a restored Linux and works again.
M8. Fast Plan 9 transport
Closes G7.
Build: a shared-memory ring transport for 9P to 9front, which needs a small 9front driver. Tbind is unchanged, and the UART-9P wire stays as a fallback.
Gate: p9 echo first-output latency is measured before and after on the same host and emulation mode, with the method recorded. The correctness gates pass on both transports, and nothing is claimed beyond the measured numbers.
M9. Lowered-driver pilot
Build: Linux's virtio-net driver lowered into a native component by the §8 procedure. Then a strangler swap: the backend behind Linux's guest-facing virtio-net moves from kernel_world_net_host.oc to the lowered component, under the same lease.
Why this driver: QEMU provides the device, and O-core's hand-written driver is a reference to compare against.
Gate:
The closure report lists every Linux symbol reached, each implemented or a sentinel with coverage evidence.
A network conformance corpus gives identical results on both backends.
A deliberate off-corpus call hits a sentinel and fails closed with its documented error.
M10. XNU hosting research
This is research only, with no claims. Asahi's m1n1 hypervisor already boots XNU as a guest under its own EL2 code on Apple silicon. On newer macOS it also boots SPTM and TXM under the hypervisor, with SPTM in emulation mode.
Deliverable: a feasibility note for Lee covering boot policy for custom boot objects, SPTM and TXM handling, how the closed drivers reach hardware, and licensing questions.
10. Agent operating rules
Agents build through the Ostadix MCP, never on their own machines, and every claim they make carries a gate result and its scope.
Tools
Discover before using: o_capabilities(query) and o_guide(topic), with topics including core, compiler and agents. Installed flags can lag the source catalog, so read a command's --help before using an unfamiliar flag.
Compile O-core modules with ocorec through o_cli: ocorec MODULE.oc --emit ast|hir|mir|asm|obj --target aarch64-unknown-none -o OUTPUT.
Build, boot and gate kernels with scripts/o-kernel.sh (the same as o kernel) through o_cli. Its help lists doctor, build, image, boot, console, smoke and gates.
Run long QEMU and build tasks as background jobs (background=true), and follow them with o_job_status and o_job_read. A job starting is not a pass.
Check the environment with o_doctor, o_env and o_runtimes before a gate, and keep the output.
After the MCP is rebuilt, reconnect before trusting its tool schemas; a running client can keep the old ones.
Where gates run
The MCP host serves a pinned release. On 2026-11-12 it reported commit 1da570dcc61ef10285fc8c8b78a20ca087081daf. Before any gate, confirm the release matches the branch under test; if it doesn't, rebuild through setup or report the mismatch instead of claiming.
Gates that need admitted builds and saved QEMU states run where those states live, which today is X12. Fork a saved state for every run, and never change a preserved state or VM.
Repository conventions
One milestone per branch and pull request, with the regression set run on each.
Gates live in scripts/verify_o10_*.py and write a result JSON into a session directory; unit tests live in tests/test_o10_*.py.
Register every new module in the language-source manifest, so scripts/check_language_sources.py check covers it.
Add docs/O10.md for the protocol once M0 lands. Update docs/CLAIMS.md only with gate-backed claims.
Follow docs/COMMIT_AUTHORS.md and docs/AI_ASSISTED_DEVELOPMENT.md for commit authorship.
Keep evidence under evidence/o10-<milestone>-<date>/, following the existing evidence/okernel-boot-20261103 pattern.
Hard rules
Never set up or build Ostadix on the agent's own machine; use the MCP.
No dummy functions, silent no-ops or automatic replays (I5, I11).
Every claim names its gate and scope (I15), and a skipped test qualifies nothing.
Stop and ask Lee before changing end-state statements, deleting a preserved experiment or saved state, granting any domain more authority than the behavior-preserving baseline, or writing physical media.
Evidence record
Every gate result records:
the milestone and gate ID;
the source revision and the MCP release;
the host, QEMU version and machine options;
the exact command lines and session directory;
the result JSON and its pass or fail; and
the claim's scope, in one sentence.
